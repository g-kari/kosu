# Kosu（工数）設計メモ

作成: 2026-11-14。サービス名は **Kosu**、公開先は **https://kosu.0g0.xyz**、リポジトリは g-kari/kosu（public）。

## 概要
- 工数（作業時間）記録とタスク管理を一体にしたサービス
- ガントチャート表示あり
- MCP 対応：エージェント（Claude Code / Codex / dsh 等）からタスク・工数を操作できる
- ログインは OIDC（0g0-id を IdP として利用、認可コード＋PKCE）
- Cloudflare Workers + D1 + R2、0g0.xyz のサブドメインで公開

## テナント方式と階層
- **マルチテナント**。階層は **テナント → ワークスペース → チーム → プロジェクト → タスク** の4階層
- すべてのデータ（タスク・工数・同期・暗号化キー）はテナント単位で分離する
- アカウントは複数のテナントに所属できる。API・同期・MCP はすべてテナントを明示して操作する

## 権限設定
- 階層ごとにメンバーとロールを持つ（上位の管理権限は下位へ継承される）
  - テナント：owner / admin / member
  - ワークスペース：admin / member（テナント admin 以上は継承）
  - チーム：lead / member（ワークスペース admin は継承）
  - プロジェクト：admin / editor / viewer（チーム lead は editor 以上を継承）
- 権限チェックは対象リソースの階層で行い、上位ロールを持てば下位の操作も可能にする

## データモデル（D1）
- accounts：OIDC の sub は対応表の中だけに保持し、画面・API には内部アカウント ID のみ出す（Hyo の PR #25 と同じ方針）
- tenants / tenant_members：テナントと所属（ロール付き）
- workspaces / workspace_members：テナント配下
- teams / team_members：ワークスペース配下
- projects / project_members：チーム配下。開始日・期限・色
- tasks：タイトル、説明、ステータス（todo/doing/done 等）、担当者、開始予定・期限（ガント用）、親タスク（サブタスク）、並び順
- time_entries：タスク紐付け、開始・終了（または duration）、メモ。タイマー開始/停止と手入力の両対応
- links：タスクへの外部リンク。種別 = slack / linear / github_commit / github_pr / url。URL と外部 ID、タイトルキャッシュ
- linear_sync：Linear 連携設定（対象チーム/プロジェクト、最終同期時刻、外部 ID ↔ タスク ID 対応）
- audit_log：管理操作の履歴

## 同期アーキテクチャ（ローカルファースト）
- Linear と同じ方式：**クライアントがローカル DB を持ち、サーバーとは差分同期する**
- 画面の読み書きはローカル DB に対して行い（高速・オフライン可）、同期エンジンがサーバーと差分をやり取りする
- サーバー（D1）は同期データの置き場に徹する

## 暗号化
- ローカルファーストにより、**サーバー側は暗号化されたデータだけを保持する**（平文はクライアント側でのみ扱う）
- 同期ペイロードはクライアント側で AES-GCM 暗号化してから送る。鍵の管理方式（アカウント鍵の生成・端末間共有）は実装時に確定する
- サーバー側で必要な最小限のメタデータ（同期順序、更新時刻、所有アカウント ID 等）の範囲は実装時に切り分ける

## 認証・認可
- OIDC：0g0-id、認可コード＋PKCE S256、セッションは署名付き Cookie
- MCP / API 用に API キー発行（スコープ付き、失効可）

## MCP
- /mcp エンドポイント（Streamable HTTP）。ツール：タスク CRUD、工数の開始/停止/記録、ガント用データ取得、リンク追加、Linear 同期状態確認
- 認証は API キーまたは OIDC トークン

## 外部連携
- Slack：メッセージリンクをタスクに紐付け（リンク種別として保存。必要なら後段で内容取得）
- GitHub：コミット・PR の URL/番号をタスクに紐付け。PR の状態（open/merged/CI）は GitHub API で表示時に補完
- GitHub Issues：**自動連携でタスク化**。指定したリポジトリの Issue を取り込み、タスクとして作成・更新する（外部 ID で重複防止）
- Linear：**自動連携でタスク化**。指定した Linear チーム/プロジェクトの Issue を取り込み、タスクとして作成・更新する（外部 ID で重複防止）。双方向同期か片方向（取り込みのみ）かは実装時に確定する

## プラグイン同梱
- リポジトリに plugins/ を置き、Codex / Claude Code / dsh それぞれの形式で MCP 接続設定と利用スキルを提供する

## 画面
- タスク一覧（カンバン兼用）、ガントチャート（プロジェクト／タスクの期間バー、依存は後段）、工数カレンダー・集計（日別・タスク別・プロジェクト別）、タイマー

## 機能要件（2026-11-14 に全部入りで確定）

### 必須級
- 見積もりと実績の比較（予定工数 vs 実績、超過の見える化）
- タスクの依存関係とマイルストーン（ガントに反映）
- 稼働カレンダー（営業日・休日設定。集計と期限計算の前提）
- 時間の丸め設定（15分単位など、テナント／ワークスペース単位）
- 集計レポートと CSV/JSON 書き出し（月次締め・請求用）
- タイマーの放置検知と同時実行の制限
- メンバー招待フロー（階層ごとのロール付与とセット）
- 同期の競合解決方針（ローカルファースト用。方針は実装時に確定し記録する）
- ゴミ箱と復元、監査ログ

### 追加分
- ラベル・タグ、保存フィルター、全文検索
- 繰り返しタスクとテンプレート
- 締切リマインドと通知（アプリ内＋ Webhook）
- コメントとメンション
- 添付ファイル（R2 保存）
- ダッシュボード（今日の工数、今週の合計、進行中一覧）
- テナント単位のデータ書き出し（バックアップ）

### 第2弾（2026-11-14 に全部入りで確定）
- 工数の提出・承認フローと月次ロック
- 単価と予算（メンバー単価、プロジェクト予算 → コストと請求額の算出）
- 他ツールからの移行インポート（Toggl / Clockify / Kimai / CSV）
- PWA 対応
- 同期ステータスの可視化（未同期件数・競合の表示）
- タスクの変更履歴と復元
- セッション管理（ログイン中端末の一覧と失効）
- テナントごとの利用量と上限（タスク数・メンバー数など）
- カスタムフィールド
- ステータスと優先度のカスタマイズ（ワークフロー設定）
- 一括編集とアーカイブ
- 休暇・欠勤の記録（稼働カレンダーと連動）
- Google カレンダー連携（予定と工数の対照・取り込み）
- Slack 通知（完了や締切の投稿）
- TimeCrowd 連携（API 経由で工数・タスクの取り込みと同期）
