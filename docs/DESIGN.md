# Kosu（工数）設計メモ

作成: 2026-11-14。サービス名は **Kosu**、公開先は **https://kosu.0g0.xyz**、リポジトリは g-kari/kosu（public）。

## 概要
- 工数（作業時間）記録とタスク管理を一体にしたサービス
- ガントチャート表示あり
- MCP 対応：エージェント（Claude Code / Codex / dsh 等）からタスク・工数を操作できる
- ログインは OIDC（0g0-id を IdP として利用、認可コード＋PKCE）
- Cloudflare Workers + D1 + R2、0g0.xyz のサブドメインで公開

## テナント方式と階層
- **マルチテナント**。階層は **テナント → ワークスペース → チーム → プロジェクト → タスク** の4階層
- すべてのデータ（タスク・工数・同期・暗号化キー）はテナント単位で分離する
- アカウントは複数のテナントに所属できる。API・同期・MCP はすべてテナントを明示して操作する

## 権限設定
- 階層ごとにメンバーとロールを持つ（上位の管理権限は下位へ継承される）
  - テナント：owner / admin / member
  - ワークスペース：admin / member（テナント admin 以上は継承）
  - チーム：lead / member（ワークスペース admin は継承）
  - プロジェクト：admin / editor / viewer（チーム lead は editor 以上を継承）
- 権限チェックは対象リソースの階層で行い、上位ロールを持てば下位の操作も可能にする

## データモデル（D1）
- accounts：OIDC の sub は対応表の中だけに保持し、画面・API には内部アカウント ID のみ出す（Hyo の PR #25 と同じ方針）
- tenants / tenant_members：テナントと所属（ロール付き）
- workspaces / workspace_members：テナント配下
- teams / team_members：ワークスペース配下
- projects / project_members：チーム配下。開始日・期限・色
- tasks：タイトル、説明、ステータス（todo/doing/done 等）、担当者、開始予定・期限（ガント用）、親タスク（サブタスク）、並び順
- time_entries：タスク紐付け、開始・終了（または duration）、メモ。タイマー開始/停止と手入力の両対応
- links：タスクへの外部リンク。種別 = slack / linear / github_commit / github_pr / url。URL と外部 ID、タイトルキャッシュ
- linear_sync：Linear 連携設定（対象チーム/プロジェクト、最終同期時刻、外部 ID ↔ タスク ID 対応）
- audit_log：管理操作の履歴

## 同期アーキテクチャ（ローカルファースト）
- Linear と同じ方式：**クライアントがローカル DB を持ち、サーバーとは差分同期する**
- 画面の読み書きはローカル DB に対して行い（高速・オフライン可）、同期エンジンがサーバーと差分をやり取りする
- サーバー（D1）は同期データの置き場に徹する
- 差分同期は変更ログ方式：テナント単位の単調増加シーケンス（seq）を各変更に割り振り、クライアントは `since_seq` で pull、push はエンティティごとの `version`（楽観ロック）を `base_version` として送る
- 同期対象エンティティ：タスク、工数、タスク依存関係、マイルストーン
- **競合解決方針（フェーズ2で確定）**：既定は「サーバー側の最新を正とする」。push の `base_version` がサーバーの現在 `version` と一致しない変更は適用せず、競合として `sync_conflicts` にサーバー版・クライアント版の両ペイロードを記録する。競合は同期ステータス API で件数が見え、クライアント側にも競合として残る。目で見て選ぶ解決画面（差分プレビュー）はフェーズ3
- 同期端末はアカウント単位で登録し（名前・プラットフォーム）、一覧・失効ができる。失効した端末の push/pull は拒否する

## 暗号化
- ローカルファーストにより、**サーバー側は暗号化されたデータだけを保持する**（平文はクライアント側でのみ扱う）
- 同期ペイロードはクライアント側で AES-GCM 暗号化してから送る
- **鍵管理（フェーズ2で確定）**：アカウント鍵（ADK）はクライアント側で生成する。ADK は復旧コードから PBKDF2-HMAC-SHA256 で導いた鍵でラップ（AES-GCM）し、サーバーはラップ済み鍵と復旧コードの SHA-256 ハッシュだけを保持する（ADK 平文・復旧コード平文はサーバーに置かない）。新しい端末では復旧コードを入力して ADK を復元する。復旧コードは発行時に1回だけ表示する
- クライアント側で暗号化するフィールド：タスク説明、工数メモ、プロジェクト説明（いずれも `*_enc` 列に暗号文で保存し、サーバーは不透明な文字列として扱う）。タイトルや名前、ステータス、日時などのメタデータはサーバー側の一覧・ガント・集計に必要なため平文
- **サーバー側の FIELD_ENCRYPTION_KEY の用途は連携トークン類（Linear / GitHub 等の外部連携トークン）の保存に限定する**。ユーザーデータ本文の暗号化には使わない

## 認証・認可
- OIDC：0g0-id、認可コード＋PKCE S256、セッションは署名付き Cookie
- MCP / API 用に API キー発行（スコープ付き、失効可）

## MCP
- /mcp エンドポイント（Streamable HTTP）。ツール：タスク CRUD、工数の開始/停止/記録、ガント用データ取得、リンク追加、Linear 同期状態確認
- 認証は API キーまたは OIDC トークン

## 外部連携
- Slack：メッセージリンクをタスクに紐付け（リンク種別として保存。必要なら後段で内容取得）
- GitHub：コミット・PR の URL/番号をタスクに紐付け。PR の状態（open/merged/CI）は GitHub API で表示時に補完
- GitHub Issues：**自動連携でタスク化**。指定したリポジトリの Issue を取り込み、タスクとして作成・更新する（外部 ID で重複防止）
- Linear：**自動連携でタスク化**。指定した Linear チーム/プロジェクトの Issue を取り込み、タスクとして作成・更新する（外部 ID で重複防止）。双方向同期か片方向（取り込みのみ）かは実装時に確定する

## プラグイン同梱

## 画面
- フェーズ6（v0.7.0）で Web UI を本格化した（`src/routes/ui.ts`）。詳細は docs/PHASE6.md
- トップ `/` はブラウザ向け HTML ランディング（概要・ログイン導線・/terms・/privacy）。JSON のサービス識別は /health と /api/health に寄せた（`/` は Accept: application/json のときだけ従来の JSON を返す互換を残す）
- /app は共通シェル（サイドバー、テナント／ワークスペース／プロジェクト切替、実行中タイマーの常時表示、コマンドパレット、テーマ・言語は user_prefs 連携）＋ダッシュボード／タスク／工数／ガント／レポート／設定の6画面。実装はサーバーサイド生成＋プレーン JS が既存 API を呼ぶ自己完結方式（外部 CDN なし）
- タスクの説明・コメントは暗号文（description_enc / body_enc）のまま API を往復し、ブラウザ内でアカウント鍵（ADK）により復号する。ADK は復旧コードでローカルにアンラップし sessionStorage にのみ保持する。サーバーは平文を受け取らない
- UI が必要とした読み取り API を2件追加：GET /api/v1/me（所属テナントと既定テナント付き。フェーズ2〜5の画面 JS が参照していたが未実装だったものを実装）、GET /api/v1/tenants/:tenantId/members（担当者選択と名前解決用）

フェーズ2の実装メモ（確定事項）：
- タイマーは1アカウントにつき実行中1件まで（開始時に既存の実行中があれば 409）。実行中・停止後を通じて12時間を超える工数は `long_running` として記録し、警告表示に使う
- 時間の丸めは集計時にエントリ単位で適用する（既定15分・四捨五入、テナント設定。ワークスペース設定で上書き可）。保存する実績値は丸めない
- 稼働カレンダーはテナント単位：週次パターン（既定は月〜金が営業日）に日付単位の上書き（休日・営業日）を重ねる
- 招待はメール送信基盤がないため、招待リンク（トークン付き URL）の発行と表示まで。トークンはハッシュで保存し、有効期限は7日。受理はログイン中アカウントがリンクを開いて行う
- 鍵のローテーション：現在の復旧コードの提示を条件に、ラップ済み鍵と復旧コードを差し替えられる（PUT /api/v1/me/encryption-key に rotate 指定）。復旧コードを失うとサーバー側では復旧できない（サーバーはハッシュしか持たないため）
- 工数エントリの変更は本人のみ（同期 push も同様）。REST の直接編集だけはプロジェクト管理者・テナント管理者も可
- ワークスペースの丸め上書きはフィールド単位で継承し、null を送るとそのフィールドの上書きを解除してテナント設定に戻る
- クライアントライブラリ（client/ 配下、プレーン JS ESM）：local-db.js（IndexedDB 実装＋メモリ実装、outbox 付き）、vault.js（ADK 生成・復旧コード・PBKDF2 ラップ、暗号文形式はサーバーと同じ `v1.` 形式）、sync-engine.js（push/pull/status）。Worker からは配信せず、テストで担保する（配信組み込みは後段）
- ダッシュボードの「進行中一覧」は自分が担当者（assignee）の doing タスク（最大50件）。工数の今日/今週は自分のエントリを開始日基準で集計する
- タイマー停止時に実行中がなければ 409（TIMER_NOT_RUNNING）、依存関係の循環は 400（DEPENDENCY_CYCLE）で返す

#### フェーズ3の実装メモ（2026-11-14、v0.4.0）
- **検索の分担**：サーバー側検索（GET /tenants/:id/search）は平文メタデータのみ（タスクタイトル、プロジェクト名、マイルストーン名、ラベル名。読み取り権限のある範囲に限定）。タスク説明・工数メモ・コメント本文はクライアント側暗号化のためサーバーでは検索できない。暗号化本文の全文検索はクライアント側で行う（client/search.js の ClientSearchIndex が復号済み本文をメモリ上に索引化する。平文索引は永続化しない）
- **ラベル**：スコープは tenant / workspace / project の3段で、プロジェクトで見えるのは3スコープの和集合。付与はラベルのスコープがタスクをカバーする場合のみ。色は #RRGGBB
- **ワークフロー定義**：ステータス／優先度とも解決順は project → workspace → tenant → 既定（ステータス todo/doing/done、優先度 low/medium/high/urgent）。PUT でスコープの定義集合を置換し、`renames`（旧 slug → 新 slug）で同スコープ配下のタスクを一括移行する。DELETE でスコープ定義を消すと上位継承へ戻る。REST のタスク作成・更新は解決済み定義で検証する。同期 push は検証しない（オフライン側の未知 slug を競合処理に委ねるため）
- **タスクの priority は列として保持**（tasks.priority、既定 medium）。アーカイブは archived_at で表し、既定の一覧からは除外する
- **繰り返し**：完了（done カテゴリ）への遷移で次回分を生成する（タイマー実行ではない）。ルールは次回タスクへ移り generated_count を加算、end_date / max_count で停止。次回のステータスは解決済み定義の最初の open カテゴリ
- **テンプレート**：payload はルートタスク＋ subtasks の木（日付は instantiate の base_date からの日数オフセット）。タスク複製はサブタスク木ごと深いコピーで、ラベルとカスタムフィールド値をコピーし、工数エントリはコピーしない
- **コメント**：本文は body_enc（クライアント暗号化。サーバーは読めない）。メンションはクライアントが内部アカウント ID の配列で渡し、テナント所属をサーバーが検証する。投稿者は自動でウォッチャーになる
- **添付**：バイト列は R2（キー `att/{tenantId}/{taskId}/{attachmentId}`）、メタデータは D1。上限 10 MiB。ダウンロードは必ず API 経由でプロジェクト読み取り権限を検証し、公開 URL は作らない
- **変更履歴と復元**：タスクの作成・更新・削除・アーカイブ等を task_history にスナップショット付きで記録し、任意の履歴時点へ復元できる。ゴミ箱はタスク／工数エントリの論理削除一覧で、復元と完全削除（purge、テナント管理者のみ）ができる。purge は従属するフェーズ3の行も物理削除し、同期ログへ delete を追記する
- **レポート**：期間は開始日基準（UTC、最大366日）。集計単位は project / member / task / day。丸めはエントリ単位で適用（ワークスペース解決）。コストは `丸め後秒 / 3600 × 単価（セント/時）` を整数セントへ丸め、請求額も同額とする（単価・予算とも通貨は3文字コード、既定 JPY）。メンバー別には期待値（稼働カレンダーの営業日 − 休暇日数）× 8時間を付け、プロジェクト別には予算と超過フラグを付ける。CSV は format=csv、印刷・PDF 向けは GET /tenants/:id/report/print の HTML
- **提出・承認とロック**：提出は期間が重なる active な提出があると 409（SUBMISSION_OVERLAP）。提出中／承認済みの期間は所有者本人の変更を 403（ENTRY_FROZEN）で拒否し、管理者は編集可。月次ロック（period_locks）は開始日の UTC 月で判定し、全員（管理者含む）の直接変更を 403（PERIOD_LOCKED）で拒否する。ロック中の唯一の例外は承認済み修正申請の適用経路。修正申請は edit / create / delete の3種で create は代理入力の申請形も兼ねる。代理入力の直接形（管理者が即時記録）も用意する
- **通知**：種別は task_assigned / task_updated / comment / mention / submission_submitted / submission_decided / change_request_created / change_request_decided / deadline_reminder / sync_conflict の10種。アプリ内通知は dedupe_key で重複防止し、行為者本人は除外。Webhook はテナント単位のエンドポイントへ受信者ごとに1回、署名は `x-kosu-signature: sha256=<HMAC-SHA256 hex>`（鍵はエンドポイントのシークレット。FIELD_ENCRYPTION_KEY で暗号化保存し、平文は作成時に1回だけ返す）。購読は events 配列で種別を列挙する（`"*"` で全種別。空配列は購読なし）。配信結果は webhook_deliveries に記録
- **通知の細分化**：設定は (account, tenant) 単位で種別ごとに in_app / webhook の ON/OFF と静音時間（ローカル分＋TZ オフセット、跨日対応）を持つ。静音時間は Webhook のみ抑制し、アプリ内通知は記録する
- **締切リマインド**：Worker の Cron（毎時）で実行。期限超過（dedupe は日次）・当日・前日を担当者とウォッチャーへ通知する。日付判定は UTC 基準
- **競合の差分プレビュー**：GET /tenants/:id/sync-conflicts/:id が両ペイロードとフィールド別比較（server / client / differs）を返す。解決は server 採用（現状維持で閉じる）か client 採用（現在のサーバー状態の上にクライアントペイロードを新規変更として適用。payload が null なら削除）。画面は /app/conflicts（最小実装）。競合の発生はテナント管理者へ、解決は発生者へ通知する。競合を見られるのは発生者本人とテナント管理者
- **同期対象の追加はなし**：フェーズ3の新エンティティ（ラベル等）は同期対象に含めていない（同期対象はフェーズ2の task / time_entry / task_dependency / milestone のまま）。priority などタスクの新フィールドはタスクのペイロードに含まれる

#### フェーズ4の実装メモ（2026-11-14、v0.5.0）

- **MCP**: `POST /mcp`（Streamable HTTP、ステートレス JSON-RPC 2.0）。認証は API キー（Bearer、キーのテナントが既定）またはセッション。スコープ判定はツール単位（読み取り専用キーは書き込みツールを isError で拒否。トランスポートが POST でも読み取りを許可するため）。ツールは15件（タスク CRUD、工数記録とタイマー、ガント取得、リンク参照・追加、連携一覧・手動同期、ダッシュボード）。詳細は docs/MCP.md
- **プラグイン**: plugins/ に実物を同梱。Claude Code は `.claude-plugin/plugin.json` + `.mcp.json` + `skills/kosu/SKILL.md`、Codex は `config.toml`（bearer_token_env_var）+ `AGENTS.md`、dsh は `mcp.json` + `SKILL.md`。キーは全形式とも環境変数 `KOSU_API_KEY` 経由で、ファイルに実キーを書かない
- **連携の共通基盤**（migration 0005）: `integration_connections`（provider、取り込み先プロジェクト、config_json、secret_enc＝トークンの暗号文、webhook_secret_enc、enabled）。トークンは書き込み専用で再表示しない。未設定の接続は「未接続」と明示し、外部へは一切アクセスしない。同期履歴は `integration_sync_runs`（manual / webhook / import）。重複防止は `external_items` の (tenant_id, provider, external_id) 一意索引
- **Linear / GitHub Issues**: 手動同期（API 取得、前回成功時刻以降を対象）と Webhook（接続作成時に受付 URL + シークレットを1回だけ発行、HMAC-SHA256 署名検証）の両対応。取り込みは片方向（Issue → タスク）で確定。本文はコピーしない（クライアント暗号化のため）。タスクへのリンクを自動で付け、状態はカテゴリ（open/doing/done）へ写す。ローカルで削除したミラータスクは復活させない
- **PR マージで自動完了**: タスクの `github_pr` リンク（外部 ID の既定は PR の URL）と Webhook の照合で実施。監査ログに記録する
- **Slack**: リンク種別 `slack` の紐付けと、通知イベントの Incoming Webhook 投稿（テナントの有効な slack 接続へイベントごとに1回）。チャンネル名 config は表示用ラベル
- **Google カレンダー**: サービス側に OAuth 資格情報が未設定のため、設定画面と未接続表示、状態 API（理由と到達範囲の明示）まで。予定取り込みは資格情報の設定後に有効化する設計として明記
- **iCal フィード**: アカウント単位でトークン発行（ハッシュ保存、失効可）。自分が読めるプロジェクトの期限つきタスクを終日イベントで配信する
- **メールでタスク作成**: プロジェクト単位の受付トークン（ハッシュ保存）へ転送サービスが JSON を POST する形。実メールボックス接続は範囲外
- **TimeCrowd**: 手動同期でタスク・工数を取り込み（外部 ID で重複防止、工数は実行者のものとして記録）
- **移行インポート**: Toggl / Clockify / Kimai / 汎用 CSV と ActivityWatch JSON。内容ハッシュで冪等化（上限 5,000 行）。ActivityWatch は30秒未満を除外しアプリ別タスクへの下書きにする。説明文はコピーしない
- **テナント書き出し**: オーナーのみ。暗号化フィールドは暗号文のまま、秘密情報（トークン類・ハッシュ・セッション等）は除外し `has_secret` フラグのみ残す
- **設定画面**: `/app/settings/integrations`（連携 CRUD・同期・履歴、iCal フィード、メール受付トークン、Google カレンダー状態、書き出し導線）

#### フェーズ5の実装メモ（2026-11-14、v0.6.0）

- **自動化ルール**（migration 0006、`src/automation.ts`）: トリガは task_created / task_status_changed / task_assigned / pr_merged。条件は from_status / to_status / assignee_account_id（すべて任意、AND）。動作は set_status / set_assignee / notify（担当・ウォッチャー・テナント管理者）。ルールはテナント全体またはプロジェクト単位。実行は呼び出し側（REST / MCP / GitHub Webhook）から行い、ルールの動作はエンジンを再入させない（無限ループ防止）。全実行（一致・不一致・失敗）を automation_runs に記録。CRUD は `/api/v1/tenants/:tenantId/automation-rules`
- **プロジェクトテンプレート**（`src/project-templates.ts`）: プロジェクト全体（タスク・依存・マイルストーン）を日付オフセット付き JSON として project_templates に保存し、開始日を指定して別プロジェクトとして展開する。フェーズ3の単体タスク用テンプレート（task_templates）とは別物
- **完了ベースの繰り返し**: recurrence_rules に basis（schedule = 従来、completion = 完了日基準で次回日付を決め、開始→期限の期間は維持）を追加
- **カスタムレポート**: report_definitions（フェーズ3レポートのパラメータ＋範囲 last_days / this_month / last_month / custom＋スケジュール off / daily / weekly / monthly）。手動実行と Cron 実行の結果は report_runs に保存し、作成者へ report_ready 通知（アプリ内＋Webhook）。メール基盤がないため配信はこの2経路のみ
- **見積もり単位**: tasks に estimate_points（数値）と estimate_size（XS/S/M/L/XL）を追加し、分数見積もりと併記可能にした。REST / MCP の両方で入出力可
- **締切エスカレーション**（`src/escalation.ts`）: テナント単位の設定（既定は無効）。段階1=期限の before_days 日前に担当者、段階2=超過 overdue_admin_days 日に担当＋ウォッチャー＋プロジェクト管理者＋テナント管理者、段階3=以降 repeat_days ごとに段階2の宛先へ再送。フェーズ3の基本リマインドとは dedupe キー（`esc:` 接頭辞）で分離
- **PWA**: /manifest.webmanifest、/sw.js（アプリシェルのキャッシュ。API・認証はキャッシュしない）、/icons/icon.svg。全画面の shell に manifest リンクと SW 登録を含む
- **表示設定**: user_prefs（テーマ system/light/dark、言語 ja/en、週の開始曜日 ISO 1-7）をアカウント単位で保存し、画面のテーマ・ダッシュボードの週集計に反映
- **多言語（i18n の範囲）**: 辞書方式（`src/i18n.ts`、日英）。辞書経由にするのはアプリシェルのナビゲーション、ダッシュボードの見出し、表示設定画面、初期設定画面、利用規約・プライバシーのタイトル、コマンドパレットの定型文まで。API のエラーメッセージと業務画面の細かなラベルは日本語のまま（今後追加する文言は辞書へ先に入れる）
- **コマンドパレット**: Cmd/Ctrl+K で開く `<dialog>`。タスク横断検索（既定テナントの全プロジェクト）、タスク作成（先頭プロジェクトへ）、画面移動。矢印キー＋Enter＋Esc のキーボード操作完結
- **利用量と上限**（`src/usage.ts`）: tenant_limits（メンバー数・タスク数・添付容量、NULL=無制限）。到達時は作成系 API が 422 limit_exceeded（タスク作成 REST/MCP、添付、招待受理で強制）。利用量は GET .../usage で表示
- **API キーの IP 制限**: api_keys.ip_allowlist（IPv4 / IPv4 CIDR / IPv6 完全一致）。認証時に cf-connecting-ip（なければ x-forwarded-for）と照合し、範囲外は 403。発行時指定と PATCH での変更に対応
- **ログインアラート**: login_events に全ログインを記録。(IP, User-Agent) の組が初出の場合のみ login_alert をアプリ内通知（初回ログインは通知しない）
- **アクセシビリティ**: スキップリンク、全要素の :focus-visible アウトライン、パレットの listbox セマンティクス、共有ページの progressbar ロール、コントラストの高い警告色（#e07b00 のフォーカスリング等）を shell に統一適用
- **大量タスク最適化**: タスク一覧にキーセットページング（limit + cursor、(sort_order, created_at, id) のカーソル。未指定時は従来どおり全件）を追加。インデックスは tasks(project_id, sort_order, created_at)、tasks(tenant_id, due_date)、time_entries(tenant_id, account_id, started_at)
- **進捗の公開リンク**: public_share_links（トークンはハッシュ保存、失効・期限つき）。/share/:token で完了率・ステータス別件数・期間・マイルストーンのみを表示（タスク名・本文は出さない）
- **タスク受付フォーム**: intake_forms（プロジェクト単位トークン）。/intake/:token はタイトル必須のみ、ハニーポット欄つき、同一フォーム1時間10件のレート制限（intake_submissions で計数）。作成タスクはフォーム作成者のアカウントで記録
- **アカウント削除**（`src/purge.ts`）: セッション認証のみ。確認はアカウントのメールアドレス（なければ "DELETE"）の入力。プレビュー（GET /api/v1/me/deletion-preview）で所有テナントと引き継ぎ要否を提示。オーナーのテナントは「後継者を指定して引き継ぎ」か「解散（テナントごと物理削除、R2 オブジェクト含む）」のどちらか必須で、どちらもない場合は削除を拒否。存続テナント内の作成物は後継者へ付け替え、nullable な参照は NULL 化、本人の個人データ（鍵・セッション・端末・通知・設定・ログイン履歴・所属）は物理削除。残存参照があれば失敗として中断（fail closed）
- **全体管理画面**: 運営者は環境変数 OPERATOR_ACCOUNT_IDS（内部アカウント ID のカンマ区切り）で指定。GET /api/v1/admin/overview（セッション＋運営者のみ）がテナント一覧・利用量・連携状態（provider と有効フラグのみ）を返す。sub・資格情報は出さない
- **利用規約・プライバシー**: /terms、/privacy にプレースホルダー文面を公開ページとして用意
- **初期設定ウィザード**: /app/onboarding（手順ガイド＋サンプルデータ操作）。サンプルは専用ワークスペース配下にプロジェクト＋タスク3件を投入し、sample_projects で追跡して削除可能にする
