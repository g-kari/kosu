# フェーズ9：オフライン対応（v0.10.0）

## 読み取り（Service Worker のデータキャッシュ）
- GET /api/v1/ はネットワーク優先。成功（200）したら `kosu-data-v1` キャッシュへ保存し、ネットワークが落ちているときはキャッシュから返す
- キャッシュしないもの：暗号化キー、テナント書き出し、添付ダウンロード、同期エンドポイント、CSV 形式のレポート（DATA_DENY）
- ログアウト（POST /auth/logout）を検知したらデータキャッシュを破棄する
- シェルキャッシュは kosu-shell-v3（オフライン用スクリプトも含む）

## 書き込み（アウトボックス）
- 共有スクリプト offline.js が window.fetch を包み、/api/v1/ への変更系リクエストがネットワークエラーになったら IndexedDB（kosu-offline/outbox）へ保存して 202 を返す
- 復帰時（online イベント、読み込み時、60秒間隔）に順番どおり再送。2xx で削除、4xx は破棄して件数を状態バーに表示、5xx・通信エラーは残して次回再試行
- 状態バー（画面左下）：オフライン表示、未送信件数、破棄件数を出す
- キューしないもの：APIキー・各種トークン・暗号化キー等の「一度だけ表示される秘密」を返す作成操作、添付アップロード等のバイナリ送信

## タイマーの時刻
- オフラインで押した開始／停止が再送時刻で記録されないよう、timer/start は client_started_at、timer/stop は client_stopped_at を任意で受ける
- 検証：未来（2分の時計ずれまで許容）と7日より古い時刻は 400。停止が開始より前も 400

## 限界（正直なところ）
- キューした作成は、送信が済むまで一覧に現れない（一覧は前回取得のキャッシュ表示になる）。状態バーで未送信件数を明示する
- アウトボックスはブラウザごと。別端末には引き継がれない
- 競合時はサーバー側の版数チェックが優先され、負けた変更は 409 で破棄され件数が表示される
