# フェーズ8：クライアントパフォーマンス（v0.9.0）

## 課題（実測、フェーズ7時点）

全ページが共通 CSS（8,619B）と共通 JS を HTML にインラインで埋め込んでいたため、画面遷移のたびに同じコードを再ダウンロードし、再パースしていた。ページ別の内訳（HTML バイト数）：

| ページ | 合計 | うち共通CSS | うちスクリプト |
|---|---|---|---|
| / | 12,217 | 8,619 | 0 |
| /app | 37,458 | 8,619 | 24,955 |
| /app/tasks | 54,880 | 8,619 | 39,593 |
| /app/time | 39,920 | 8,619 | 27,050 |
| /app/gantt | 34,084 | 8,619 | 22,536 |
| /app/settings | 37,570 | 8,619 | 24,785 |

スクリプトのうち全画面共通の UI コア（13,158B）とコマンドパレット（4,307B）、タスク/設定画面のボールトパネル（1,793B）は毎回重複していた。

## 対応

- 共通 CSS・UI コア・パレット・ボールトの4資産を、内容ハッシュ付き URL（`/assets/<name>-<hash>.<ext>`、FNV-1a）の外部ファイルとして配信し、`Cache-Control: public, max-age=31536000, immutable` を付与（src/routes/public5.ts）。内容が変われば URL が変わるため、古い資産が残る心配はない
- シェル（src/routes/pages.ts）は `<style>` インラインを stylesheet リンクへ変更。wide レイアウト用の上書きスタイルは `body.wide` クラス＋CSS ルールへ移行。appPage（src/routes/ui.ts）は外部スクリプトタグをインラインスクリプトの前に並べ、ページ固有スクリプト（データを含む）だけを従来どおり nonce 付きインラインに残した
- CSP（src/index.ts）は script-src / style-src-elem に `'self'` を追加し、nonce と併用。印刷ビュー（ops.ts）のインライン style は nonce で従来どおり動く
- Service Worker はキャッシュ名を kosu-shell-v2 に上げ、SHELL_URLS に4資産を追加（オフライン時もシェルが成立する）

## 結果（同じ実測方法での比較）

| ページ | 前 | 後 | 削減 |
|---|---|---|---|
| / | 12,217 | 3,607 | −70% |
| /terms | 10,632 | 2,022 | −81% |
| /app | 37,458 | 11,388 | −70% |
| /app/tasks | 54,880 | 27,065 | −51% |
| /app/time | 39,920 | 13,850 | −65% |
| /app/gantt | 34,084 | 8,014 | −76% |
| /app/settings | 37,570 | 9,755 | −74% |

2回目以降の表示では、共通資産（合計 約28KB）はブラウザキャッシュから読まれ、転送もパースも発生しない。タスク画面がなお大きいのは、ページ固有の TASKS_SCRIPT（約19KB、画面データを含むためインライン継続）が残るためで、次に削るならこの分割が候補になる。

## テスト

- test/phase8.test.ts（新規3件）：資産の immutable ヘッダーと内容、アプリ画面が共通スクリプトを参照しインラインに含まないこと、ページ重量の上限
- フェーズ5・7のテストは、CSS の中身（:focus-visible、prefers-reduced-motion、timer-dot）を資産側で確認するよう更新
- 全167件通過（従来164件＋フェーズ8の3件）
